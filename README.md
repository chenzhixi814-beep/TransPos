# TransPos

WGS84 / CGCS2000 坐标与速度转换工具，Python + Tkinter GUI，无第三方依赖。

## 运行

```bash
python main.py
```

需要 Python 3.8+（仅使用标准库：`tkinter`、`math`、`dataclasses`）。

## 功能

### 1. 坐标转换（Tab: 坐标转换）
- 支持 WGS84 与 CGCS2000 互转
- 输入可选 大地坐标 (纬度 B / 经度 L / 大地高 H) 或 地心直角坐标 (X / Y / Z)
- 输出同时给出目标坐标系下的 BLH 与 XYZ

### 2. 位置/速度转换（Tab: 位置/速度转换）
- 地心系位置 + 速度 (X, Y, Z, VX, VY, VZ) ←→ 大地坐标 + 东北天速度 (B, L, H, VE, VN, VU)
- 双向转换，速度转换基于给定点处的 ECEF→ENU 旋转矩阵

### 3. 参数设置（Tab: 参数设置）
- 查看 WGS84 / CGCS2000 椭球参数（长半轴、扁率倒数、第一偏心率平方）
- 编辑 WGS84 → CGCS2000 的七参数 Bursa-Wolf 转换参数（默认全 0）

## 关键假设与注意事项

- **WGS84 与 CGCS2000 默认视为重合**：两者都是与 ITRF 框架对齐的坐标系，在常规测绘精度下差异在厘米级以下，官方未发布统一的七参数转换值。工具默认使用全零七参数；如你持有特定区域/项目的转换参数，可在“参数设置”页手动填入。
- **两个椭球的扁率并不完全相同**（WGS84 的 1/f = 298.257223563，CGCS2000 的 1/f = 298.257222101），因此 BLH↔XYZ 转换分别使用各自的椭球参数，避免把基准差异和椭球形状差异混在一起。
- **大地坐标 → 地心坐标（正算）有闭式公式**，是精确解；**地心坐标 → 大地坐标（反算）没有闭式解**，程序使用迭代法（Bowring 类），并采用数值稳定的高程公式 `h = p·cosB + z·sinB − a·sqrt(1 − e²sin²B)`，避免在两极附近除以接近零的 cosB 导致的精度损失。
- **大地高 (h) 不等于海拔/正高 (H)**：大地高是相对椭球面的几何高度，海拔是相对大地水准面的高度，二者相差一个大地水准面差距 N（h = H + N）。本工具只处理椭球几何量，不包含大地水准面模型，不能直接给出海拔。
- **速度转换只使用给定时刻的位置计算旋转矩阵**：这是 GNSS 领域的标准做法，忽略了当地水平坐标系自身随点位缓慢移动而产生的二阶旋转效应，对绝大多数应用可忽略。
- 输入的经纬度使用十进制度，经度范围建议使用 [-180°, 180°]（东经为正、西经为负），符号约定需要在数据源头保持一致，否则会引入低级但常见的错误。

## 目录结构

```
TransPos/
├── main.py                    # 程序入口
├── transpos/
│   ├── ellipsoids.py          # WGS84 / CGCS2000 椭球参数
│   ├── conversions.py         # BLH<->XYZ、七参数转换、ECEF<->ENU 速度转换
│   └── gui.py                 # Tkinter 界面
└── tests/
    └── test_conversions.py    # 单元测试（往返一致性、极点/赤道特殊点、旋转矩阵正交性等）
```

python -m unittest discover -s tests -v
